# Critique (verbatim findings from the independent Critic)

The Critic ran in a fresh `Explore` context with file paths only (SKILL §7). Its findings are reproduced below without edits. Coordinator's note on #1: the rendering may have lost the escape sequence; the fix applies `quality-standard.md` §8.3 as written (`<`).

| # | File | Owner-agent (role step) | Severity | Fix instruction |
|---|---|---|---|---|
| 1 | `05-components.md` (C-08), `pages/home.md` §7 | component-mapper; page-type-planner | major | Both files say the JSON-LD `<` is "escaped as `<`", which does nothing. Built as written, CMS strings go into `<script type="application/ld+json">` unescaped, which is a script-injection risk. Change both to "every `<` escaped as `<`" (quality-standard §8.3). Add a QA row: a Sanity string containing `</script>` renders inert. |
| 2 | `91-stack.md` §3, `05-components.md` C-26, `93-qa-checklist.md` F-11 | stack-advisor; component-mapper | major | `app/not-found.tsx` is rendered inside the root layout only. Also specify `global-error.tsx` as a standalone minimal page. It replaces the root layout, so it cannot render the CMS header or footer. |

Let JS set `data-header-state="top"` (transparent) only on `/` at `scrollY ≤ 8`. Add a no-JS scroll check to F-03. |
